# 漫画翻译与回填

当前聊天负责理解原文、翻译和语义复核；本地 swell-cartoon-translate 框架负责检测、OCR、编号、文件校验和排版。不要将聊天订阅当作 API，或改用之前的本地 7B/14B 模型代写译文。

## 默认与范围

- 默认简体中文；源语言不明时自动识别，主要面向英语、韩语漫画。
- 保留原文尺度、粗口、敏感含义、说话者语气和情绪，不含糊替代，也不自行强化或编写色情情节。既有内容的翻译仍遵循当前模型适用规则，技能不能豁免它们。
- 用户给漫画目录即授权在新目录完成该范围的提取、翻译和回填，不再逐批询问。用户指定张数、章节或范围时严格限定选图，不能把抽样扩成整部。
- 输出到漫画目录下新的 `聊天翻译_日期时间`，保留原图、旧项目、旧成品；私人漫画和对白不写进代码仓库或技能文件。
- 复用这次聊天已知的项目/进度；不要凭相同书名跨目录接续。长篇按章节、每批约3张推进，不把几十章对白一次读入上下文。

## 准备与恢复

使用随技能提供的 `scripts/comic.py`，用 `python -X utf8` 运行。脚本会定位框架；找不到时可传 `--repo`，框架位置通过环境变量 `CTT_REPO` 或参数 `--repo` 指定。不要拼接用户路径到动态脚本代码，使用独立参数并正确引用路径。

```powershell
python -X utf8 <skill-dir>/scripts/comic.py prepare "漫画目录或.cttproj" --run "新的运行目录" --source-lang ko
python -X utf8 <skill-dir>/scripts/comic.py status "运行目录"
python -X utf8 <skill-dir>/scripts/comic.py finish "运行目录"
```

- 已有匹配原图的 OCR 项目时，目录准备可加 `--project "项目.cttproj"`；不加载不相关项目。旧OCR复用只通过位置、尺寸和时间检查，不能称为原文已校读。
- 没有项目就让 prepare 完成检测和 OCR，翻译模型不会加载。只测试若干张时用 `--limit N`；连续章节用该章节目录，不要用全书加数量限制代替用户指定的中段。
- prepare 会保存每页 OCR、原图摘要与选图范围，再生成 `翻译包/request-*.json` 及空的 `reply-*.json`。不要拿旧译文当新译文依据。
- 恢复时先 status，读取 `人物与术语.json`，继续最早的未完成批次。OCR中断可用完全相同参数和同一 `--run` 再 prepare。原图或范围变化时使用新运行目录，不能篡改校验摘要绕过错误。
- prepare 失败先检查错误；缺依赖或识别失败不能伪装成“没有对白”。修复可恢复的问题并继续，确实缺少所需条件时准确报告阻塞原因。

## 翻译与质量

1. 读取当前 request 的原文、前后文、图片路径和人物术语。按实际章节和页码辨认连续性；非连续样本不得补出中间情节。可读取同章邻页原文澄清主语。
2. 翻译前查看原图或相关对白区域，核对阅读顺序、OCR异常、说话者及动作指向；不必对每个无歧义字反复截图。不确定的噪声、漏字、水印、遮字单独辨认，不编造呻吟补空。
3. 直接撰写当前批的 reply：保持 `package_id` 和每条 `id`，填写 `target_text` 与 `notes`。编号对应坐标；不能靠译文内容或重排后的数组位置回填。可用脚本保存由当前聊天实际撰写的译文，不能用循环复制原文、替换词典或让本地模型生成后冒充聊天译文。
4. 在写入完成批次前，对照原文再审一遍：
   - 谁说话、谁做动作、动作作用于谁；韩语省略主语和称呼特别检查。
   - 否定、反问、时态、先后顺序、请求和陈述有没有改变。
   - 敏感词、多义词和动作是否准确且保留原文语域；不能只看是否出现露骨词。
   - 人名、亲属关系跨页是否一致；术语表按语境使用，不机械替换所有同形词。
   - 译文要像自然对白；跨气泡断句既要顺，也不能合并、遗漏或挪动编号。
5. 在 `人物与术语.json` 持续记录有依据的人物关系、称呼、场景摘要及未解疑问，方便跨批和压缩上下文后恢复。把不确定之处写进对应 notes；能通过原图查清就先查，不把旧机器误译固化为人物设定。
6. 保存每批 reply 后调用 status，确认没有编号错误，再继续下一批。记录 `译文复核.json`（批次、检查过的语义问题、修正摘要、仍待核实的编号）；这是一份操作记录，不能冒充独立人工验收或准确率评测。

## 回填与交付

- 全部批次完成后 finish。它会严格检查翻译包、漏译、空译、重复编号、原图变化，并输出 `成品/project.cttproj`、图片、`成品/对照检查.html` 和检查报告。
- 输出后查看排版，至少覆盖首末页及所有文字溢出、识别噪声和语义疑问页；复核字形、残留原文、位置、裁切和阅读顺序。格式校验通过不代表翻译正确，同模型自评也不等于人工验收。
- 若只需改译文，保留初版并使用新结果目录重新导入；不要删除已有成品来绕过“不覆盖”检查。完成状态只在图片和项目都实际生成后报告。
- 大批任务在当前聊天持续推进并保存进度；不得声称技能能在聊天结束后继续后台翻译或保证一轮无限量完成。跨上下文依靠磁盘进度继续。
- 最终给结果链接、完成张数、未解疑问和必要限制。不承诺百分之百准确；若仍有不清楚的台词，清楚指出，不因为想交付“全部通过”而隐藏它。

一句话调用示例：`用 $comic-translate 翻译「漫画目录」的第5话，保留原文尺度，完成检查后放到新文件夹。`
